# Shared project conventions

1. Read status.md and resources/README.md before starting work. status.md is the shared progress source of truth; archived notes may be historical.
2. Maintain the numbered, report-oriented timeline in status.md. For each update record the local date, concrete work, result, report requirement affected, evidence link, and next action. Update the relevant milestone/R/E task; preserve historical entries. Distinguish calculated, implemented, tested, measured, analyzed, written, and submitted. A generic completed/checklist row is not an adequate update. Never imply another agent's unobserved work has completed.
3. Keep kernel source and workflows in the working folders. Preserve frozen inputs, original run contents, archive bytes and checksum sidecars. Add a new run or analysis rather than overwriting old evidence.
4. Archive superseded work by purpose/experiment step under archives/. Retain run identifiers as provenance within the step; do not use an unexplained date as the only browsing category.
5. Historical results paths, build/ and .idea include compatibility symlinks. Do not remove them casually or recurse through them when creating archive inventories. Use archives/README.md for canonical locations.
6. Keep hand-in exports in resources/. Edit report sources first, then run python3 tools/refresh_resources.py. Review the resource readiness notes and source hashes after updating.
7. The full alignment matrix is complete; the LaTeX report and presentation still need reconciliation. Do not repeat older statements that the full matrix is pending without labeling them historical. Completion of a run does not establish repeatability of every timing cell.
8. Do not execute target kernels locally to refresh documentation. Follow the recorded ECE protocol for any new target experiment. Keep active diagnostic preparation separate from evidence of native execution.
9. Use status.md for progress; completion.json and results/processed/measurement_status.json remain detailed existing records. Reconcile them when changing scientific or submission status, with supporting evidence.
10. User requirement: assembly generation, disassembly and inspection must happen on ECE only. Never generate proxy assembly or inspect assembly on the Mac, including downloaded ECE assembly. Preserve frozen ECE evidence; use ECE-produced inspection summaries for documentation. The Mac assembly preview and its inspection artifacts were deleted at the user's request on 30 October 2026 and must not be recreated.
